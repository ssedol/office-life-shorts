# 08. 자동화 설계

> 전제: **주제 수집 → 업로드까지 전자동**으로 간다.
> 이 문서는 그 전제 위에서 지금 구조를 어떻게 잡아야 나중에 갈아엎지 않는지를 정한다.

## 0. 가장 먼저 — 자동화와 채널 전략이 충돌하는 지점

**전자동 = 사람 손이 안 탄 영상 = YouTube가 지금 가장 강하게 단속하는 형태다.**

2025년 7월, YouTube는 수익화 정책의 `repetitious content`(반복 콘텐츠)를
**`inauthentic content`(비진정성 콘텐츠)** 로 바꾸고 기준을 넓혔다. 대상은
"**진짜 사람의 창작이 없는 콘텐츠**" — 구체적으로 **템플릿만 갈아끼운 대량 생산물**,
**AI 음성이 텍스트를 읽어주는 슬라이드쇼**, **영상 간 차이가 거의 없는 반복물**이다.
2026년에는 개별 영상이 아니라 **채널 단위로 평가**하는 쪽으로 집행이 강화됐다.

**중요한 건 "AI를 썼는가"가 아니라 "고유한 창작이 있는가"다.** AI 사용 자체는 허용된다.
→ 따라서 목표는 *자동화를 포기하는 것*이 아니라, **파이프라인의 어느 지점에 사람 고유의
입력을 넣을지 설계하는 것**이다.

### 이 저장소가 택한 방어선

| 방어선 | 구현 |
|---|---|
| 모든 영상에 사람 고유 요소 1개 이상 | `production.human_elements` 필드. 비면 `scripts/validate.py`가 WARN |
| 육성 나레이션 유지 | `synthetic_voice: false` 를 기본값으로. TTS는 예외 처리 |
| 템플릿 반복 차단 | 후킹 패턴·화면 구성을 회차마다 강제 로테이션 (§3 05단계) |
| 합성물 사용 시 고지 | `synthetic_*`가 true인데 `ai_disclosure`가 없으면 **FAIL**(업로드 차단) |
| 업로드 직전 사람 승인 | 1단계에서는 **반자동**. 완전 무인 업로드는 §5 조건 충족 후 |

> **판단**: 전자동을 목표로 하되, **`06_upload` 앞에 사람 승인 게이트를 두고 시작**하는 것을 권한다.
> 무인 업로드로 얻는 시간은 하루 10분이고, 잃을 수 있는 건 채널 전체다.

## 1. 설계 원칙 — "규칙은 데이터, 문서는 해설"

나중에 자동화하려면 **파이프라인이 읽을 수 있는 형태로 규칙이 존재해야 한다.**
그래서 이 저장소는 규칙을 산문에서 분리했다.

| 종류 | 위치 | 읽는 주체 |
|---|---|---|
| **규칙(데이터)** | `config/*.yaml`, `data/topics.yaml` | 사람 + 스크립트 + LLM |
| **산출물(데이터)** | `output/*.json` (`schema/script.schema.json` 준수) | 스크립트 |
| **해설(산문)** | `docs/*.md` | 사람만 |

**원칙: 같은 사실을 두 곳에 쓰지 않는다.** 금지어를 바꾸려면 `config/channel.yaml`
한 곳만 고치면 되고, 검수 스크립트와 생성 프롬프트가 동시에 따라온다.

## 2. 지금이 수동이어도 형식은 이미 자동화 형식이다

오늘 대본을 손으로 써도 **`output/NNNN.json`** 으로 쓴다. 그러면 나중에 LLM이
같은 JSON을 뱉게만 하면 되고, **그 뒤 단계(검수·렌더·업로드)는 코드를 그대로 재사용**한다.
"나중에 자동화"가 "나중에 전면 재작성"이 되는 걸 막는 유일한 방법이다.

## 3. 파이프라인 7단계

```
01_collect   주제 수집     → data/topics.yaml 에 append
02_select    주제 선별     → 스코어링 후 status: idea → queued
03_script    대본 생성     → output/NNNN.json  (LLM)
04_validate  검수 게이트   → scripts/validate.py   ★ 실패 시 여기서 멈춤
05_produce   영상 생성     → TTS + 자막 + 렌더
06_approve   사람 승인     → ★ 1단계에서는 필수
07_upload    업로드        → YouTube Data API
08_measure   지표 수집     → YouTube Analytics API → 01로 되먹임
```

| 단계 | 현재 상태 | 자동화 난이도 | 비고 |
|---|---|---|---|
| 01 수집 | 수동 (`data/topics.yaml`) | **낮음** | 자기 채널 댓글 API가 1순위 소스 |
| 02 선별 | 수동 | 중 | 스코어 함수 설계가 핵심 |
| 03 대본 | 수동 + 프롬프트 | 낮음 | `prompts/generate-shorts.md` + JSON 출력 강제 |
| 04 검수 | **완료** ✅ | — | `scripts/validate.py` 이미 동작 |
| 05 제작 | 미착수 | **높음** | 여기가 병목이자 품질 리스크 |
| 06 승인 | — | — | 의도적으로 사람 |
| 07 업로드 | 미착수 | 중 | API 할당량 확인 필요 (§4) |
| 08 지표 | 미착수 | 중 | 되먹임이 있어야 자동화가 의미 있음 |

### 01 수집 — 소스 우선순위

1. **자기 채널 댓글** (YouTube Data API `commentThreads.list`) — 합법, 무료, 품질 최상.
   시청자가 자기 사례를 직접 써준 것이라 그대로 다음 대본이 된다. **여기부터 자동화한다.**
2. **자기 채널 검색어/추천 데이터** (YouTube Analytics API)
3. ⚠️ **커뮤니티 크롤링** — 권장하지 않는다. 사이트 이용약관 위반 소지, 저작권,
   그리고 무엇보다 **남의 글을 긁어 만든 콘텐츠는 §0의 비진정성 판정에 정면으로 걸린다.**
   소재 참고는 사람이 눈으로 하고, 문장은 새로 쓴다.

### 02 선별 — 스코어 함수(초안)

```
score = 0.4 * 유사주제_과거성과
      + 0.3 * 댓글_출현빈도
      + 0.2 * 축_비중_보정      # config/axes.yaml 의 active_mix 를 맞추는 방향
      + 0.1 * 최신성
      - 0.5 * 최근_30일_유사주제_발행     # 반복 콘텐츠 판정 회피
```
마지막 항이 §0 방어선이다. **비슷한 걸 연달아 내보내지 않게 코드가 강제한다.**

### 04 검수 — 이미 동작하는 게이트

```bash
./scripts/validate.py output/0001.json     # 종료 코드 0/1
```
FAIL 항목: 금지어, 블록 누락/순서, 분량(발음 글자 210~240), HOOK 추상성·길이,
후킹 후보 3개 미만, CTA 비질문, 제목 25자 초과, 해시태그 개수, **AI 고지 누락**.
→ 자동화되면 이 스크립트가 **05로 넘어가는 유일한 관문**이다.

### 05 제작 — 최대 병목이자 최대 리스크

| 방식 | 자동화 | 비진정성 위험 | 판단 |
|---|---|---|---|
| 본인 육성 + 책상/손 촬영 | 부분 (편집만) | **낮음** | ⭐ 권장 출발점 |
| 본인 육성 + 자동 자막/렌더 | 높음 | 낮음 | ⭐ 현실적 목표 |
| TTS + 자동 생성 비주얼 | 완전 | **높음** | 대량 반복 시 위험 |
| TTS + 스톡영상 템플릿 | 완전 | **매우 높음** | §0이 지목한 바로 그 형태 |

> **권장: 음성만 사람이 남긴다.** 녹음은 45초짜리라 하루 5개를 몰아 떠도 15분이면 끝난다.
> 자동화의 대부분 이득(대본·자막·렌더·업로드)은 그대로 가져가면서 §0 리스크를 크게 줄인다.

### 08 지표 — 되먹임이 없으면 자동화가 아니라 양산이다

`평균 조회율`, `3초 이탈률`, `댓글/조회`를 회차별로 `output/NNNN.json`에 기록하고
01단계 스코어에 되먹인다. **이게 없으면 파이프라인은 같은 실수를 무한 반복한다.**

## 4. 기술 제약 — 확인된 것과 확인 못 한 것

**확인됨**
- 업로드는 YouTube Data API v3 `videos.insert`.
- Google Cloud 프로젝트 기본 일일 할당량은 **10,000 units**.

**확인 못 함 / 충돌**
- `videos.insert` 비용에 대해 자료가 엇갈린다. 오랫동안 **1,600 units/건**(≈ 하루 6건)로
  알려져 왔으나, **2026년 6월 1일자로 별도 버킷에서 1 unit/건, 일 100건**으로 바뀌었다는
  서술이 있다. **1차 출처로 확인하지 못했다 — 근거 부족.**
  → **구현 전에 Google 공식 [Quota Calculator](https://developers.google.com/youtube/v3/determine_quota_cost)로
  직접 확인할 것.** 블로그 수치를 믿고 설계하지 않는다.
- OAuth 앱이 미검증 상태면 업로드 영상이 **비공개로 잠기는** 제약이 있다고 알려져 있다.
  자동 업로드를 붙이기 전에 **앱 검증 절차를 먼저 확인**해야 한다. 확실하지 않음.

## 5. 완전 무인 업로드로 넘어가도 되는 조건

아래가 **전부** 충족되기 전에는 `06_approve`를 사람이 지킨다.

- [ ] 발행 30편 이상, 그중 검수 게이트가 잡아낸 오류율이 안정적으로 낮음
- [ ] `08_measure` 되먹임 루프가 실제로 돌고 있음
- [ ] 최근 30편에서 후킹 패턴·화면 구성이 실제로 분산됨 (반복 판정 회피 확인)
- [ ] 합성 음성/영상을 쓴다면 AI 고지가 100% 자동으로 설정됨
- [ ] 정책 위반 경고 0건

## 6. 다음에 만들 것 (우선순위)

1. `pipeline/03_script.py` — `config/*.yaml`을 읽어 프롬프트를 조립하고 JSON을 받아오는 생성기
2. `pipeline/01_collect.py` — 자기 채널 댓글 수집 → `data/topics.yaml` append
3. `pipeline/05_produce.py` — 녹음 파일 + JSON → 자막 번인 + ffmpeg 렌더
4. `pipeline/07_upload.py` — 업로드 (§4 할당량 확인 후)
5. `pipeline/08_measure.py` — 지표 수집 및 되먹임
